I build controls for the decisions that matter when an AI system can act: what it can do, whose approval it needs, and what evidence shows the control held.

## Start here

- **Runtime enforcement:** [ACR Standard](https://github.com/AdamDiStefanoAI/acr-standard) defines where policy, identity, and human approval meet before an agent acts. The [evidence walkthrough](https://github.com/AdamDiStefanoAI/acr-standard/blob/main/docs/evidence-walkthrough.md) shows a reference implementation in a controlled example and explains what the results do and don’t establish.
- **Pre-deployment review:** [MCP-Scanner](https://github.com/AdamDiStefanoAI/MCP-Scanner) flags risks visible in MCP code and configuration. Use it as one input to the approval decision.
- **Security evaluation:** [Adversarial Feed sample](https://github.com/AdamDiStefanoAI/adversarial-feed-sample) is the free preview of a separate commercial offering for teams evaluating their own AI agents. Sample runner flags require review and confirmation in the tool log or target system.

## The ACR Standard

I created ACR to give engineering, security, and business owners a common way to define delegated authority and verify what happens at execution time. The specification covers identity and purpose binding, behavioral policy enforcement, autonomy drift, execution observability, containment, and human authority.

[Read the specification](https://runtimecontrol.io/standard) · [Explore the reference implementation](https://github.com/AdamDiStefanoAI/acr-standard) · [Governance toolkit](https://runtimecontrol.io)
